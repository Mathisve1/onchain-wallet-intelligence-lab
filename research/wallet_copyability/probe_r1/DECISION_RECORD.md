# Decision Record — Hyperliquid Public Probe R1

## R1-DEC-001 — technical gate before market release

Accepted. Public endpoint and archive-route behavior must be proven before any archive inventory, raw retention or wallet-ledger work.

## R1-DEC-002 — source-wallet profitability is outside R1

Accepted. R1 cannot calculate or discuss wallet returns, win rate, copyability, trader skill or follower performance.

## R1-DEC-003 — closed public route set

Accepted. Exactly 17 requests and three origins are registered. A new route, request type, fixture, query window or response class requires a reviewed contract revision.

## R1-DEC-004 — documentation fixtures are not identity evidence

Accepted. The master, subaccount and vault addresses are technical fixtures. R1 may classify public response shapes but may not identify a person, organization or beneficial owner.

## R1-DEC-005 — route PASS and archive access are distinct

Accepted. A valid S3 error response can confirm the official route but produces restricted archive-access status. It cannot support completeness, inventory or download claims.

## R1-DEC-006 — raw values are intentionally discarded

Accepted. R1 stores only content hashes, coarse response classes, top-level schema features, counts, timing and errors. The raw body is never written to disk or supplied to AI.

## R1-DEC-007 — terminal status is derived

Accepted. Human prose, a workflow conclusion or a manually entered field cannot override exact observation coverage and response classes.

## R1-DEC-008 — artifact before terminal failure

Accepted. The workflow captures an immutable evidence artifact even when static checks, transport, response classification or independent validation fail.

## R1-DEC-009 — attestation is separate from execution

Accepted. The read-only workflow cannot write its own attestation. A later reviewed record binds commit, run, job, artifact and output identities.

## R1-DEC-010 — rejected predecessors remain negative evidence

Accepted. PR #1 and PR #2 are rejected pre-run test-design attempts and must never be relabeled as successful R1 evidence.

## R1-DEC-011 — human-in-the-loop boundary remains unchanged

Accepted. R1 creates no order, account action or authorization. All integration, paper, shadow, live, leverage and capital-allocation booleans remain false.

## R1-DEC-012 — next gate is not automatic

Accepted. Even a fully attested `PUBLIC_PROBE_PASS` permits only a separate proposal for archive inventory. No data partition opens automatically.
